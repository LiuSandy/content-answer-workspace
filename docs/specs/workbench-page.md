# 工作台页面需求规格

## 一、页面定位

路由：`/workbench`

核心定位：一个独立的"待处理队列"，问题从其他页面流入，在这里统一管理和生成 AI 回答。

---

## 二、页面布局

### 顶部操作栏（URL 直接导入）

| 区域 | 内容 |
|------|------|
| URL 输入框 | 粘贴知乎问题链接，例如 https://www.zhihu.com/question/… |
| 平台选择器 | 知乎 / … |
| 导入按钮 | "导入问题" |
| 状态行 | URL解析 · 待检查 · 回答生成 待执行 · 本地保存 未保存 |

### 左侧：问题列表面板

| 区域 | 内容 |
|------|------|
| 搜索栏 | 搜索标题、摘要、关键词 |
| 状态筛选器 | 下拉或 chip filter：全部 / 未生成 / 已生成（非 Tab） |
| **平台 Tab** | shadcn/ui `<Tabs>` 组件：全部 / 知乎 / 小红书，切换显示各平台问题 |
| 列表内容 | 问题条目，显示题目、主题、平台标签 |
| 底部 | 计数 + 分页 |

### 右侧：回答工作区

| 区域 | 内容 |
|------|------|
| 内容约束 | 提示词配置（继承采集时的配置） |
| 编辑区 | 选中问题后显示题目 + Markdown 编辑器 |

---

## 三、数据流程

```
方式 1：CollectPage → 批量勾选问题 → 点击"加入工作台"（本期实现）
方式 2：WorkbenchPage 顶部 → 粘贴 URL → 点击"导入问题"
方式 3：ChatPage → 导入（后续迭代，本期不做）
                    ↓
            WorkbenchPage 问题列表（Zustand 前端会话状态，刷新后清空）
                    ↓ 选择问题 → 点击"生成回答"
            AI 生成 → 右侧编辑区展示 → 用户编辑
```

### 每条问题携带的属性

| 字段 | 说明 |
|------|------|
| `id` | 去重键（来源 URL 或唯一标识） |
| `title` | 问题标题 |
| `platform` | 来源平台（知乎 / 热榜 / 对话等） |
| `topic` | 主题（采集时的搜索词） |
| `promptConfig` | 提示词配置（继承采集时的设置） |
| `status` | 生成状态（未生成 / 已生成） |
| `answer` | 生成的回答内容 |

## 四、已确认决策

| # | 问题 | 决策 |
|---|------|------|
| Q1 | 数据持久化 | 前端会话状态（Zustand），刷新后清空，无需后端接口 |
| Q2 | Tab 设计 | 移除状态 Tab，状态改为 filter；仅保留平台 Tab，使用 shadcn/ui `<Tabs>` 组件 |
| Q3 | 导入入口 | CollectPage 增加批量勾选 + "加入工作台"按钮；ChatPage 导入后续迭代 |
| Q4 | 重复导入 | 按 `id`（URL）去重，已存在则跳过 |

## 五、CollectPage 改造要点

- 问题列表每条增加 checkbox
- 顶部增加"已选 N 条"提示 + "加入工作台"按钮
- 点击后将勾选问题（含 platform / topic / promptConfig）写入 workbench store
- 重复问题静默跳过，完成后 toast 提示"已加入 N 条"
